# 🎯 КВИК-СТАРТ: Как использовать систему документации

## 🚀 3 простых шага для добавления новой функции

### Шаг 1: Выберите шаблон промпта
Перейдите в [`docs/guides/prompt-templates.md`](guides/prompt-templates.md) и выберите подходящий шаблон.

### Шаг 2: Заполните шаблон
```
## 🎯 Запрос на новую функцию

### Название функции
[ВАШЕ НАЗВАНИЕ]

### Описание
[ЧТО ДОЛЖНА ДЕЛАТЬ ФУНКЦИЯ]

### Требования
- [ТРЕБОВАНИЕ 1]
- [ТРЕБОВАНИЕ 2]

### Ссылки на спецификации
- docs/specs/[ФАЙЛ].md
- docs/api/[ФАЙЛ].md

### Пример использования
[КАК ПОЛЬЗОВАТЕЛЬ БУДЕТ ИСПОЛЬЗОВАТЬ]
```

### Шаг 3: Отправьте промпт
AI проанализирует документацию и реализует функцию автоматически!

## 📋 Популярные шаблоны

### ➕ Новое действие бота
```markdown
Добавь действие "[НАЗВАНИЕ]" которое [ОПИСАНИЕ]

Требования:
- Принимает [ПАРАМЕТРЫ]
- Проверяет [ВАЛИДАЦИЯ]
- Показывает [UI]

Смотри docs/specs/ProgAction-enum.md
```

### 🎨 Новый UI компонент
```markdown
Добавь [ТИП КОМПОНЕНТА] "[НАЗВАНИЕ]" для [НАЗНАЧЕНИЕ]

Требования:
- Расположение: [ГДЕ]
- Функции: [ЧТО ДЕЛАЕТ]
- Интеграция: [С ЧЕМ]

Смотри docs/architecture/components.md
```

### 🔧 Новый сервис
```markdown
Добавь сервис "[НАЗВАНИЕ]" для [НАЗНАЧЕНИЕ]

API:
- [МЕТОД1](параметры) -> результат
- [МЕТОД2](параметры) -> результат

Смотри docs/api/services-api.md
```

## 🎯 Примеры готовых промптов

### Действие "Телепортация"
```
Добавь действие "TeleportToCoordinates" для телепортации бота на координаты.

Требования:
- Принимает X,Y координаты (0-255)
- Диалог ввода "X,Y"
- Валидация границ карты
- Категория: Movement

Смотри docs/specs/ProgAction-enum.md
```

### Панель шаблонов
```
Добавь боковую панель "Program Templates" с готовыми шаблонами.

Требования:
- Категории: Mining, Building, Combat
- Drag & drop в сетку программатора
- Сохранение пользовательских шаблонов
- Ширина 300px, всегда видима

Смотри docs/features/ui-components.md
```

### Экспорт в JSON
```
Добавь экспорт программ в JSON формат для обмена и отладки.

Требования:
- Человеко-читаемая структура
- Включает метаданные (версия, дата, страницы)
- Поддержка импорта обратно
- Без компрессии

Смотри docs/specs/Program-format.md
```

## ✅ Чек-лист перед отправкой промпта

- [ ] **Ясно ли название?** (не "сделай лучше", а "добавь валидацию X")
- [ ] **Конкретные требования?** (не "быстро", а "загружается <500ms")
- [ ] **Ссылки на документацию?** (docs/specs/ или docs/api/)
- [ ] **Примеры использования?** (как пользователь будет взаимодействовать)
- [ ] **Тип функции указан?** (CORE/UI/SERVICE/UTIL)

## 🚨 Когда добавлять детали

### Добавьте если:
- Функция сложная или уникальная
- Есть специфические UI требования
- Нужна интеграция с существующими функциями
- Есть ограничения производительности
- Требуется особая обработка ошибок

### Не добавляйте если:
- Функция тривиальная (ясна из названия)
- Следует стандартным паттернам проекта
- Нет особых требований к UI/UX
